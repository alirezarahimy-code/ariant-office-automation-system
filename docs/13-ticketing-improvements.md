## ۰. نقطه‌قوت‌ها (تا نقد منصفانه بماند)

- **هدرهای امنیتی سطح بالا:** CSP با nonce، X-Frame-Options، nosniff — در سیستم‌های داخلی کمیاب است
- رمز با `password_verify` (هش استاندارد)؛ هیچ `echo` مستقیم ورودی کاربر یافت نشود
- قفل حساب (login_attempts با پنجره و locked_until)، CSRF دوکاناله، api_rate_limits
- **CI فعال:** GitHub Actions با PHP 8.2، syntax check، SecurityTest، ArchitectureTest، تست منطق غذا
- LDAP v3 با گزینه‌های درست؛ انضباط مستندسازی (changelog شماره‌دار) و ابزارهای diag

## ۳. نقص‌های کوچک — 🟢

- `ENFORCE_HTTPS=false` پیش‌فرض؛ استقرار XAMPP تک‌سرور بدون صف و تست بار
- `custom_fields JSON` بدون ایندکس → فیلتر آینده کند
- توابع سراسری با پیشوند (traffic_، food_ticket_) بدون composer autoload/PSR
- پوشش تست نامتوازن: غذا خوب است؛ **گردش تیکت (ماشین حالت + SLA) تست خودکار ندارد**
- اعلان‌ها فقط درون‌سامانه‌ای (ایمیل/پیامک عمداً خاموش) — برای سامانه عملیاتی یعنی هشدارها دیده نمی‌شوند خارج از پنل

## ۴. راستی‌آزمایی‌نشده‌ها (صادقانه)

- جاروب کامل SQLi/XSS روی هر ۴۰ هزار خط (نمونه‌گیری منفی بود، نه پیمایش کامل)
- رفتار تحت بار واقعی و حجم زنده DB (دسترسی ندارم)
- سیاست نگهداری/حجم پیوست‌ها و بکاپ‌گیری بازیابی‌آزموده‌شده

## ۵. درس‌ها برای پلتفرم (که ساختاری حل می‌شوند)

مهاجرت جنگو: DDL زمان اجرا → مایگریشن؛ نقش دوگانه → تک‌منبع IAM؛ روتر غول → app per module؛ سیلوها → یک DB با مرز ماژولاری؛ تست گردش → آزمون ماشین حالت از روز اول؛ کلیدها → settings + secret manager.
