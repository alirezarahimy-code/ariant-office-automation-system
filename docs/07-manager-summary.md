# ۱. هدف جلسه و موارد نیازمند توافق

> این خلاصه برای تصمیم‌گیری در جلسه تهیه شده است. جزئیات فنی و درخت کامل ماژول‌ها در «سند جامع سامانه اتوماسیون اداری — نسخه ۲٫۰» (۷۵ صفحه) آمده است.

در این جلسه، پنج موضوع زیر باید **تصویب یا تعیین تکلیف** شود:

| ردیف | موضوع | پیشنهاد کارشناسی | نتیجه جلسه |
|---|---|---|---|
| ۱ | **محدوده نهایی سامانه** (۲۰ ماژول) | تصویب حذف‌ها و موارد «وصل کن» طبق بند ۲ | |
| ۲ | **ترتیب اجرا و زمان نخستین بهره‌برداری** | تصویب فازبندی بند ۳؛ تولید محدود در پایان فاز ۱ | |
| ۳ | **۱۰ تصمیم باز مدیریتی** | تعیین تکلیف طبق بند ۴ (پیش از شروع فاز ۱) | |
| ۴ | **اتصال به سامانه تیکتینگ فعلی** | تصویب روش پل (بند ۵) + پاسخ به ۷ پرسش فنی | |
| ۵ | **منابع: تیم، سرور و بودجه پشتیبانی** | تأیید بند ۶ و تخصیص منابع فاز ۰ | |

**چرا این جلسه مهم است؟** تا زمانی که محدوده و ترتیب اجرا تصویب نشود، شروع فاز ۰ به معنی ریسک دوباره‌کاری است. پس از تصویب، کار با فاز ۰ (هسته) آغاز می‌شود و نخستین ارزش کاربردی (مکاتبات بدون کاغذ) در پایان فاز ۱ تحویل می‌گردد.

# ۲. دامنه نهایی سامانه (تصمیم بساز / وصل کن / حذف)

## ۲.۱ ماژول‌های اصلی و وضعیت آن‌ها

| فصل | ماژول | اهمیت | اولویت | تصمیم |
|---|---|---|---|---|
| ۱ | هسته فنی و زیرساخت | الف | P0 | بساز |
| ۲ | مدیریت هویت و دسترسی | الف | P0 تا P1 | بساز |
| ۳ | تشکیلات و چارت سازمانی | الف | P0 تا P1 | بساز |
| ۴ | دبیرخانه و مکاتبات | الف | P0 تا P1 | بساز |
| ۵ | گردش کار و فرایندها | ب | P1 تا P2 | بساز |
| ۶ | مدیریت اسناد و بایگانی | ب | P1 تا P2 | بساز |
| ۷ | جلسات و مصوبات | ب | P1 تا P2 | بساز |
| ۸ | وظایف و پیگیری امور | ب | P1 تا P2 | بساز |
| ۹ | فرم‌ساز پویا | ج | P3 | به‌تعویق |
| ۱۰ | اطلاع‌رسانی و ارتباطات | ب | P0 تا P2 | بساز |
| ۱۱ | گزارش‌گیری و داشبورد | ب | P1 تا P3 | بساز |
| ۱۲ | امنیت و حسابرسی | الف | P0 تا P2 | بساز |
| ۱۳ | محتوا و پورتال سازمانی | ج | P2 تا P3 | بساز محدود |
| ۱۴ | یکپارچه‌سازی (پل تیکتینگ) | الف | P0 تا P2 | بساز + وصل کن |
| ۱۵ | تنظیمات و مدیریت سیستم | ب | P0 تا P2 | بساز |
| ۱۶ | منابع انسانی | ج | P2 | بساز سبک / وصل کن |
| ۱۷ | عملیات و پشتیبانی | د | P2 تا P3 | به‌تعویق |
| ۱۸ | مدیریت دانش | ج | P2 | بساز |
| ۱۹ | مالی و تدارکات | د | P3 | حذف حسابداری / فرم سبک |
| ۲۰ | سیستم‌های پشتیبان | د | P3 | حذف نوبت‌دهی / به‌تعویق |

**راهنمای درجه اهمیت:** الف = حیاتی (بدون آن سامانه قابل استفاده نیست) | ب = بسیار مهم (ارزش روزانه) | ج = مهم | د = مفید | هـ = اختیاری

## ۲.۲ موارد حذف‌شده از دامنه (نیازمند تأیید مدیریت)

| مورد | تصمیم | دلیل |
|---|---|---|
| حسابداری و اسناد مالی | حذف | نیاز سازمان نیست؛ دامنه تخصصی و قانونی جداگانه دارد |
| نوبت‌دهی و قرار ملاقات | حذف | کاربرد داخلی در اتوماسیون اداری ندارد |
| یکپارچگی تقویم بیرونی (Google Calendar) | حذف | جایگزین: تقویم شمسی داخلی سامانه |
| درگاه پرداخت | حذف | خارج از محدوده اتوماسیون اداری |
| حقوق و دستمزد | وصل کن | به سامانه موجود متصل می‌شود؛ بازسازی نمی‌شود |

## ۲.۳ موارد به‌تعویق‌افتاده (فاز ۳)

| مورد | تصمیم | دلیل |
|---|---|---|

## ۲.۴ ادغام‌های انجام‌شده (رفع همپوشانی نسخه ۱)

| موارد ادغام‌شده | نتیجه |
|---|---|

| گردش‌های کار موازی و مشابه | یک موتور گردش کار واحد (قاعده طلایی سند) |

# ۵. اتصال به سامانه تیکتینگ فعلی (الزام اصلی پروژه)

## ۵.۱ اصل کلی

سامانه تیکتینگ PHP **دست‌نخورده** می‌ماند و فقط یک لایه اتصال دریافت می‌کند. ارتباط از طریق وب‌سرویس REST و نشانه مشترک JWT انجام می‌شود؛ دو سامانه داده‌های خود را جدا نگه می‌دارند و تنها نقشه کاربران مشترک است.

| مورد | تصمیم فنی |
|---|---|
| پروتکل | HTTP/REST + JSON |
| احراز هویت | نشانه JWT با کلید مشترک (HS256، عمر کوتاه) |
| نقشه کاربران | جدول IntegrationUserMap (شناسه اتوماسیون ↔ شناسه تیکتینگ) |
| جهت ارتباط | ابتدا اتوماسیون به تیکتینگ، فقط‌خواندنی |
| زمان اجرا | فاز ۱ (نخستین اتصال بیرونی سامانه) |

## ۵.۲ دو سناریوی تحویل‌شده در فاز ۱

| سناریو | آنچه کاربر می‌بیند |
|---|---|
| ورود یکپارچه (SSO) | ورود یک‌بار به اتوماسیون؛ باز شدن تیکتینگ بدون رمز مجدد |
| نمای تیکت‌ها در کارتابل | بخش «تیکت‌های من» در کارتابل اتوماسیون (فقط‌خواندنی) |

## ۵.۳ پرسش‌های فنی از سازمان (لازم برای شروع کار پل)

| ردیف | پرسش | پاسخ سازمان |
|---|---|---|
| ۱ | تیکتینگ با چه چارچوبی نوشته شده است (لاراول یا سفارشی)؟ | |
| ۲ | امکان افزودن یک ماژول کوچک به تیکتینگ وجود دارد؟ | |
| ۳ | کدام سامانه مالک کاربران است؟ (پیشنهاد: اتوماسیون) | |
| ۴ | تیکت‌ها فقط‌خواندنی نمایش داده شوند یا مدیریت کامل لازم است؟ | |
| ۵ | پایگاه‌داده تیکتینگ چیست و دسترسی فقط‌خواندنی مجاز است؟ | |
| ۶ | حجم تیکت‌های موجود و نیاز به آرشیو چقدر است؟ | |
| ۷ | الزام امنیتی خاصی برای ارتباط دو سامانه وجود دارد؟ | |
