# راهنمای ۰۵ — دروازه چندبرند دستگاه (ZK + ویردی از طریق یونیس)

## فلسفه
سامانه **به هیچ سرویس ویندوزی نیاز ندارد**. همه‌چیز درون خود Django است:

| برند | مسیر دریافت | نیازمندی |
|---|---|---|
| **ZKTeco / سازگار (ZK)** | نظرسنجی مستقیم دستگاه با `pyzk` (TCP/UDP:437) | فقط `pip install pyzk` |
| **Virdi (ویردی)** | **پل یونیس (UNIS Manager)**: خواندن لاگ از بانک یونیس یا پوشه خروجی آن | نرم‌افزار یونیس (همان که دستگاه‌های ویردی به آن وصل‌اند) |
| هر برند دیگر | ورود CSV/USB یا API پوش (`/device/api/records/`) | — |

هر دو مسیر به **یک خط لوله واحد** می‌ریزند: ثبت رکورد خام (ضدتکرار) → تبدیل به تردد →
محاسبه رکورد روزانه/ماهانه → داشبورد و گزارش‌ها. همه برندها همزمان و در کنار هم.

## نقش نرم‌افزار یونیس (UNIS)
یونیس، نرم‌افزار مدیریت رسمی دستگاه‌های **Union Community / Virdi** است (کلاینت/سرور،
بانک MS SQL / MySQL / Oracle / Access). دستگاه‌های ویردی به یونیس وصل‌اند و لاگ تردد
در بانک یونیس می‌نشیند. سامانه ما **از بانک/خروجی یونیس می‌خواند** — نه مستقیم از دستگاه —
و بنابراین هیچ تداخلی با مدیریت کارت/اثرانگشتِ خود یونیس پیش نمی‌آید.

## تنظیم — حالت پوشه خروجی (ساده‌ترین)
۱) در یونیس (یا فرآیند خروجی‌گیری)، پوشه‌ای مشترک روی سرور سامانه تعریف کنید.
۲) در منوی «دستگاه‌ها ← پل یونیس (Virdi)»: نام پل + دستگاه مقصد + حالت «پوشه خروجی» + مسیر.
۳) قالب فایل CSV: `کد پرسنلی,تاریخ,ساعت` (تاریخ میلادی یا جلالی) — خط سربرگ نادیده گرفته می‌شود.

## تنظیم — حالت بانک یونیس (آنلاین‌ترین)
۱) به بانک یونیس دسترسی خواندنی بگیرید (View یا کاربر فقط‌خواندنی).
۲) روی سرور سامانه متغیرهای محیطی را تنظیم کنید (**رمز فقط از env — هرگز در کد/تنظیمات امنیتی/لاگ**):

```bash
export UNIS_DB_ENGINE=mssql          # mssql | mysql | oracle | sqlite
export UNIS_DB_NAME=UNIS             # نام بانک یونیس
export UNIS_DB_HOST=192.168.1.50
export UNIS_DB_USER=unis_reader      # کاربر فقط‌خواندنی
export UNIS_DB_PASSWORD=...          # فقط از env
# برای SQL Server: نصب درایور ODBC + بسته mssql-django
```

۳) در صفحه «پل یونیس»: نام جدول لاگ (مثلاً `T_LOG`) + ستون کد پرسنلی + ستون زمان
(+ ستون جهت در صورت وجود). نام‌های جدول/ستون فقط شناسه SQL معتبر پذیرفته می‌شوند (ضد تزریق).

## اجرای خودکار (بدون سرویس ویندوزی)
```bash
# حالت پیوسته (یک پروسه معمولی؛ روی لینوکس می‌تواند با systemd/cron اختیاری اجرا شود)
python manage.py run_device_bridge --interval 60

# حالت یک‌بارمصرف (برای cron هر دقیقه)
python manage.py pull_devices
```
یا در رابط کاربری: دکمه «همگام‌سازی دروازه» و «همگام‌سازی اکنون» هر پل.

## امنیت
- رمز بانک یونیس فقط از متغیر محیطی؛ در هیچ فایل/لاگی ذخیره نمی‌شود.
- نام جدول/ستون‌ها با الگوی شناسه‌ای سخت‌گیرانه کنترل می‌شوند (ضد SQL Injection).
- عملیات «همگام‌سازی» در لاگ ممیزی ثبت می‌شود.
- فایل‌های مصرف‌شده به پسوند `.imported` تغییر نام می‌گیرند؛ تکرار فایل/رکورد هرگز داده تکراری نمی‌سازد (ضدتکرار).
