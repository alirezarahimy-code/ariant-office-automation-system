# یادداشت اصلاحیهٔ فهرست سفارش نیابتی و پاک‌سازی متن منبع — Patch 3

این اصلاحیه فقط روی سورس توسعهٔ `food-orders-dev` تهیه شده است. آرشیوهای قبلی دست‌نخورده مانده‌اند.

## تغییرها

- پس از انتخاب و تأیید گیرندهٔ نیابتی، فهرستی از سفارش‌هایی که کاربر فعلی برای همان گیرنده ثبت کرده است نمایش داده می‌شود؛ فهرست شامل وضعیت فعال/لغوشده و تاریخ غذا و رزرو است و پس از ثبت سفارش تازه‌سازی می‌شود.
- دسترسی این فهرست در سمت سرور به مجوز `foodorder.proxy`، تأیید مجدد کد ملی همان گیرنده و محدودیت نرخ درخواست وابسته است. پرس‌وجو هم‌زمان به شناسهٔ گیرنده و ثبت‌کنندهٔ فعلی محدود است؛ کد ملی، شمارهٔ پرسنلی و اطلاعات ثبت‌کنندگان دیگر در پاسخ نیست. حداکثر ۱۲۰ سفارش آخرِ ثبت‌شده توسط همان کاربر برگردانده می‌شود.
- توضیح و فرم تأیید قدیمیِ منبع سفارش از رابط مدیر حذف شد. پیام‌های آزمون اتصال، آزمون سلامت و بارگذاری فایل نیز دیگر توضیحی دربارهٔ محل نگهداری سفارش‌ها یا ارتباط Access با سفارش‌ها نشان نمی‌دهند.
- دارایی‌های پنل (`food-menu.js` و `food-order.css`) با نسخهٔ اصلی همگام شدند و شمارهٔ cache-busting دارایی‌های تغییرکرده افزایش یافت.

## آزمون‌های اجراشده

- `python3 -m unittest tests.test_food_orders_static -v` — ۲۴ آزمون موفق.
- `node tests/test_food_order_calendar_node.js` — موفق.
- `node --check` برای دارایی‌های JavaScript تغییرکرده و JavaScript درون‌خطی `food-ticket-web/index.html` — موفق.
- `cmp` برای نسخه‌های همگام‌شدهٔ `food-menu.js` و `food-order.css` — موفق.
- آرشیو جدید با `unzip -t` و checksum اعتبارسنجی شده است.

## محدودیت تأیید

PHP CLI در این محیط موجود نیست؛ بنابراین `php -l` و آزمون‌های PHP قابل اجرا نبودند. اتصال MySQL، اجرای endpointها روی سرور مقصد، مرورگر واقعی، Worker، TENTER و چاپگر نیز از این محیط قابل آزمون نیستند. پیش از استفادهٔ سازمانی، بسته را با baseline مقصد تطبیق دهید و در staging واقعی آزمون کنید؛ ساخت ZIP به‌تنهایی تأیید استقرار نیست.
