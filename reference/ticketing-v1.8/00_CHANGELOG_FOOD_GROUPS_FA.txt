کارت گروهی غذا (Food Ticket Groups)
===================================

مفهوم
-----
کارت گروهی فقط یک «ماشه» است؛ نماینده‌ی هیچ کاربری نیست و هرگز Learn نمی‌شود.
فقط C_Card ردیف SOURCE_TABLE بررسی می‌شود (L_UID هیچ نقشی ندارد). اعضای گروه فقط با users.id شناخته می‌شوند و
نیازی به منبع تردد / کارت / اثر انگشت / ردیف SOURCE_TABLE ندارند.

اولویت تشخیص: کارت گروهی ← (مسیر فعلی) کاربر ← مهمان ← ناشناس.

رفتار
-----
- اجرای اول کارت گروه در یک روز (first): هر عضو با همان کنترل‌های فعلی کاربر بررسی می‌شود:
  فعال بودن ← کد ملی ← سفارش امروز ← فیش قبلی همان کاربر ← رویداد printed + صف چاپ (همان تابع‌های فعلی).
    * بدون سفارش → رویداد no_food      * فیش قبلی دارد → رویداد repeat      * واجد شرایط → چاپ
- اجرای مجدد همان کارت در همان روز (repeat): فقط یک رکورد خلاصه در food_ticket_group_runs؛
  بدون بررسی اعضا، بدون Event برای کاربران، بدون چاپ.
- گروه غیرفعال (inactive): فقط رکورد خلاصه؛ هیچ فیشی چاپ نمی‌شود.
- ردیف دوم SOURCE_TABLE برای همان کشیدن فیزیکی کارت (≤ ۴ ثانیه): بی‌صدا حذف می‌شود.
- ردیف SOURCE_TABLE کارت گروهی فقط وقتی حذف می‌شود که هیچ عضوی خطا نداشته باشد؛ در غیر این صورت دور بعد فقط
  اعضای پردازش‌نشده ادامه می‌یابند (source_key یکتای هر عضو، چاپ دوباره‌ای رخ نمی‌دهد).
- food_ticket_group_runs فقط برای ثبت اجرا، گزارش و تشخیص تکرار خودِ کارت گروهی است و جایگزین کنترل
  «یک فیش در روز برای هر کاربر» (ticket_key = food:تاریخ:کدملی) نیست.

فایل‌ها
-------
جدید:
  food-ticket-groups.php                 منطق گروه + API مدیریت (همهٔ منطق جدید اینجاست)
  food-ticket-web/assets/food-groups.js  صفحهٔ «تنظیمات سیستم ← گروه‌های غذا»
  upgrade-1.13-food-groups.sql           جدول‌ها (به‌صورت خودکار هم ساخته می‌شوند)
  tools/test_food_groups.php             آزمون سناریوها
تغییرکرده:
  food-ticket-engine.php   (۱) انتهای decide_punch به تابع food_ticket_decide_for_user منتقل شد (بدون تغییر رفتار) تا
                           منطق «سفارش + فیش قبلی» یک نسخه داشته باشد؛ (۲) hook کوچک در حلقهٔ process_batch_v2
  food-ticket.php          require، مسیر API ‏food-groups و نگاشت دسترسی food.groups، تزریق food-groups.js
  permissions.php          دسترسی جدید food.groups (جدا از food.guest)
  food-ticket-web/index.html  بخش «گروه‌های غذا» در تنظیمات
  schema.sql               جدول‌های جدید
بدون تغییر: food-ticket-runtime.php، food-ticket-netprint.php، cron/food_ticket_worker.php، جدول food_ticket_events.

جدول‌ها
-------
food_ticket_groups(id, title, rfid_card UNIQUE, description, status, created_at, created_by)
food_ticket_group_members(id, group_id, user_id UNIQUE ← هر کاربر فقط یک گروه, created_at)
food_ticket_group_runs(ثبت اجرا: first / repeat / inactive و شمارش‌ها)

اعتبارسنجی هنگام ذخیره
-----------------------
- گروه بدون کارت معتبر (حداقل ۴ نویسهٔ حرف/عدد) ذخیره نمی‌شود.
- کارت نباید برای گروه دیگر، کارت مهمان یا کاربری (نگاشت کارت) ثبت شده باشد.
- هر کاربر فقط در یک گروه (هم در برنامه، هم با UNIQUE(user_id) در دیتابیس).
- فهرست انتخاب اعضا فقط کاربران آزاد (و اعضای فعلی همان گروه) را نشان می‌دهد.

نصب
----
1) پشتیبان بگیرید و محتویات بسته را روی پروژه کپی کنید.
2) restart-food-worker-SERVICE.bat را (Admin) اجرا کنید (Worker فایل‌ها را فقط هنگام شروع بارگذاری می‌کند).
3) Ctrl+F5 در پنل. در «مدیریت دسترسی‌ها» دسترسی «گروه‌های غذا» را به نقش‌های موردنظر بدهید (ادمین اصلی نیازی ندارد).
4) آزمون: C:\xampp\php\php.exe tools\test_food_groups.php   (چاپ واقعی انجام نمی‌شود؛ داده‌های آزمون پاک می‌شوند)

نکته: مطمئن شوید شمارهٔ کارت گروهی در ستون C_Card جدول SOURCE_TABLE ثبت می‌شود، نه فقط L_UID.
