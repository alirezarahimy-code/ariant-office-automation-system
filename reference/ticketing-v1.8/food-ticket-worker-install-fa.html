راهنمای نصب Worker چاپ فیش غذا

ویژهٔ Windows Server · لینک‌ها و صفحات رسمی بررسی‌شده در ۳۰ سپتامبر ۲۰۲۶

اگر سامانهٔ PHP و دیتابیس MySQL/MariaDB شما همین حالا کار می‌کند، آن‌ها را دوباره نصب نکنید. Worker از PHP CLI همان سرور استفاده می‌کند؛ فقط اتصال Access، چاپگر و اجرای خودکار باید آماده شوند.

قبل از شروع: از دیتابیس نسخهٔ پشتیبان بگیرید، Worker یا سرویس C# قبلی را متوقف کنید و هم‌زمان فقط یک موتور چاپ را فعال نگه دارید. فایل XAMPP جدید را روی سرور فعلی نصب نکنید؛ نصب موازی ممکن است PHP یا MySQL دیگری راه بیندازد.

پیش‌نیازها و لینک دریافت

۱. PHP CLI و فایل‌های وابسته الزامی

PHP باید نسخهٔ ۸٫۱ یا بالاتر باشد. اگر سایت با XAMPP اجرا می‌شود، معمولاً همان فایل C:\xampp\php\php.exe را استفاده کنید؛ PHP جدا لازم نیست.

اگر ZIP مستقل Windows x64 NTS را دانلود کرده‌اید، مراحل استخراج و تنظیم آن در بخش بعد آمده است. نصب جداگانه فقط برای CLI است و جای وب‌سرور فعلی را نمی‌گیرد.

صفحهٔ رسمی PHP 8.4 برای Windowsدریافت مستقیم PHP 8.4.26 x64 NTSVisual C++ Runtime x64 (در صورت نیاز)

۲. افزونه‌های MySQL و OpenSSL و اجازهٔ اجرای فرمان الزامی

pdo_mysql برای اتصال PHP به MySQL و openssl برای بازکردن رمز Access ذخیره‌شده لازم‌اند. تابع exec امکان اجرای PowerShell و دستور چاپ را می‌دهد. افزونه‌ها همراه ZIP رسمی PHP هستند و دانلود جداگانه نمی‌خواهند؛ باید در همان PHP CLI فعال باشند و exec در disable_functions مسدود نباشد.

۳. موتور Access (ACE/OLEDB) فقط اگر ODBC آماده نیست

اگر PHP ODBC و درایور Access روی سرور کار می‌کنند، نصب دیگری لازم نیست. در غیر این صورت Worker از PowerShell و Access Database Engine استفاده می‌کند. Runtime باید با معماری Office نصب‌شده (۳۲ یا ۶۴ بیت) سازگار باشد. Microsoft نصب Runtime را در کنار نسخه‌های Office نصب‌شده با Windows Installer پشتیبانی نمی‌کند؛ در چنین سروری پیش از نصب با مدیر سیستم هماهنگ کنید.

راهنمای رسمی Microsoft 365 Access Runtimeدریافت مستقیم Runtime انگلیسی x64

۴. PowerShell و Task Scheduler داخل Windows

در Windows Server 2016 و جدیدتر، Windows PowerShell 5.1 به‌صورت پیش‌فرض موجود است. نصب‌گر از powershell.exe و Task Scheduler ویندوز استفاده می‌کند؛ PowerShell 7 جداگانه لازم نیست.

توضیح Microsoft دربارهٔ Windows PowerShell 5.1

۵. MySQL/MariaDB و phpMyAdmin از سامانهٔ فعلی

Migration را روی همان دیتابیسی اجرا کنید که سامانه به آن وصل است. اگر محیط فعلی XAMPP است، معمولاً phpMyAdmin و فرمان mysql.exe از قبل نصب‌اند. دیتابیس دوم نسازید و نصب XAMPP را روی سرور فعلی تکرار نکنید.

صفحهٔ رسمی دریافت XAMPP (فقط محیط تازه/آزمایشی)

توجه: صفحهٔ XAMPP بررسی‌شده نسخه‌های Windows قدیمی‌تری نشان می‌دهد؛ برای سامانهٔ عملیاتی، PHP فعلی سرور را حفظ کنید و فقط اگر مدیر سرور تأیید کرد چیزی نصب کنید.

۶. درایور فیش‌پرینتر بر اساس روش چاپ

برای چاپ از صف Windows، درایور لازم است. درایور رسمی سازندهٔ چاپگر یا درایور عمومی فیش‌پرینتر ۸۰ میلی‌متری را نصب کنید و تطابق آن با مدل چاپگر را بررسی کنید. برای چاپ شبکه‌ای RAW روی پورت ۹۱۰۰ ممکن است درایور Windows لازم نباشد.

استخراج و ساخت فایل تنظیمات

اگر PHP را به‌صورت ZIP دانلود کرده‌اید، محتویات آن را در C:\php84 استخراج کنید و مطمئن شوید C:\php84\php.exe مستقیم در همان پوشه است. اگر Windows پیام داد DLLهای Visual C++ پیدا نیستند، Visual C++ Runtime x64 موجود در بخش دانلود را نصب کنید. سپس در Command Prompt فایل تنظیمات پیش‌فرض را کپی کنید:

copy C:\php84\php.ini-production C:\php84\php.ini

فعال‌سازی افزونه‌ها

فایل C:\php84\php.ini را باز کنید. مسیر افزونه‌ها را تنظیم و دو افزونه را فعال کنید. اگر خطوط فعال از قبل وجود دارند، همان‌ها را ویرایش کنید و خط تکراری نسازید:

extension_dir = "C:\php84\ext" extension=pdo_mysql extension=openssl

تابع exec جزو تابع‌های PHP است، نه افزونه. اگر exec در فهرست disable_functions دیده شد، قبل از تغییر محدودیت با مدیر سرور هماهنگ کنید.

بررسی PHP آماده‌شده

در Command Prompt بررسی کنید که PHP نسخهٔ ۸٫۱ یا جدیدتر است، فایل C:\php84\php.ini بارگذاری شده و هر سه مورد آماده‌اند:

"C:\php84\php.exe" --ini "C:\php84\php.exe" -v "C:\php84\php.exe" -r "echo extension_loaded('pdo_mysql') ? 'pdo_mysql OK' : 'pdo_mysql MISSING', PHP_EOL; echo extension_loaded('openssl') ? 'openssl OK' : 'openssl MISSING', PHP_EOL; echo function_exists('exec') ? 'exec OK' : 'exec MISSING', PHP_EOL;"

PHP مستقل فقط برای Worker است و تنظیمات PHP داخل XAMPP/Apache را تغییر نمی‌دهد. در مرحلهٔ نصب Worker، مسیر C:\php84\php.exe را به نصب‌گر بدهید.

مراحل نصب و اجرا

آماده‌سازی و پشتیبان‌گیری

از دیتابیس نسخه بگیرید. در Task Scheduler یا سرویس Windows هر Worker فیش فعلی را متوقف کنید. نام دیتابیس را از تنظیمات محلی برنامه پیدا کنید؛ رمز آن را در فایل راهنما یا پیام‌ها ننویسید. فایل‌های برنامه باید روی همین سرور موجود باشند.

اجرای Migration شمارهٔ ۱٫۱۹

در همان دیتابیس برنامه، از phpMyAdmin وارد تب Import شوید، فایل upgrade-1.19-food-ticket-queue.sql را انتخاب کنید و Go را بزنید. اگر جدول food_ticket_events وجود ندارد، ابتدا migration ماژول فیش (۱٫۹) و migrationهای قبلی موردنیاز نسخهٔ دیتابیس را اجرا کنید.

راه جایگزین: این فرمان را در Command Prompt (نه PowerShell) اجرا کنید و نام دیتابیس و مسیرها را عوض کنید. با -p رمز جداگانه پرسیده می‌شود.

"C:\xampp\mysql\bin\mysql.exe" -u root -p persian_ticketing < "C:\xampp\htdocs\persian-ticketing\upgrade-1.19-food-ticket-queue.sql"

در تب SQL همان دیتابیس، این بررسی‌ها را اجرا کنید؛ باید ستون‌های صف و جدول گزارش چاپ را ببینید:

SHOW COLUMNS FROM food_ticket_events; SHOW TABLES LIKE 'food_ticket_print_log';

بررسی PHP CLI و افزونه‌ها

مسیر php.exe را با مسیر واقعی PHP سرور عوض کنید و در Command Prompt اجرا کنید. خروجی باید PHP ۸٫۱ یا جدیدتر، pdo_mysql OK، openssl OK و exec OK نشان دهد. ODBC اختیاری است؛ اگر غایب بود باید مسیر ACE بالا آماده باشد.

"C:\php84\php.exe" -v "C:\php84\php.exe" -r "echo PHP_VERSION, PHP_EOL; echo extension_loaded('pdo_mysql') ? 'pdo_mysql OK' : 'pdo_mysql MISSING', PHP_EOL; echo extension_loaded('openssl') ? 'openssl OK' : 'openssl MISSING', PHP_EOL; echo function_exists('exec') ? 'exec OK' : 'exec MISSING', PHP_EOL; echo extension_loaded('odbc') ? 'odbc OK' : 'odbc missing (ACE fallback)', PHP_EOL;"

مسیر PHP و فایل تنظیمات باید یکی باشند: اگر دستور را با C:\xampp\php\php.exe اجرا می‌کنید، فایل C:\php84\php.ini اثری روی آن ندارد. یا همهٔ آزمون‌ها و نصب Worker را با C:\php84\php.exe انجام دهید، یا افزونه‌ها را در فایل INI که خروجی --ini برای PHP انتخابی نشان می‌دهد فعال کنید. نصب‌گر مسیر PHP و INI را نمایش می‌دهد؛ همان مسیر را مبنای عیب‌یابی بگذارید.

برای PHP نشان‌داده‌شده در نمونه، فایل تنظیمات فعال C:\xampp\php\php.ini است. اگر پس از اجرای نصب‌گر به‌روز هنوز pdo_mysql واقعاً کم بود، همین فایل را باز کنید و خط extension=pdo_mysql را فعال کنید؛ اگر ابتدای آن ; دارد، فقط همان علامت را بردارید. سپس در Command Prompt فهرست افزونه‌ها را دوباره بررسی کنید:

"C:\xampp\php\php.exe" -m | findstr /I "pdo_mysql openssl odbc"

اگر خطای افزونه دیدید، تنظیمات همان PHP CLI را بررسی کنید. نصب‌گر جدید فهرست افزونه‌ها را با php -m می‌خواند تا نقل‌قول‌های PowerShell نتیجه را تغییر ندهند. پیام Module "openssl" is already loaded یعنی افزونه در INI فعال دوبار بارگذاری می‌شود؛ فقط یک خط فعال extension=openssl نگه دارید. در سرور سازمانی پیش از تغییر محدودیت‌های امنیتی با مدیر سیستم هماهنگ کنید.

تنظیم Access و چاپگر با Worker خاموش

در سامانه، صفحهٔ «چاپ فیش غذا» را باز کنید و مسیر منبع تردد، فایل سفارش، نام جدول سفارش و چاپگر را ذخیره کنید. اگر فایل‌ها روی شبکه‌اند، مسیر UNC مثل \\server\share\file.mdb بدهید؛ درایوهای Map شده ممکن است برای Task دیده نشوند. در این مرحله گزینهٔ فعال‌سازی Worker را خاموش نگه دارید.

اجرای نصب‌گر Windows

با همان حساب Windows که به Access، MySQL و چاپگر دسترسی دارد، Command Prompt را باز کنید. مسیر برنامه و PHP را متناسب با سرور عوض کنید. این آرگومان دقیقاً تعیین می‌کند کدام PHP و کدام فایل INI برای Worker استفاده شود:

"C:\xampp\htdocs\persian-ticketing\tools\install_food_ticket_worker_windows.bat" "C:\xampp\php\php.exe"

اگر PHP مستقل نصب کرده‌اید، مسیر آرگومان دوم را C:\php84\php.exe بگذارید. نصب‌گر افزونه‌های لازم و نحو PHP را بررسی می‌کند، وظیفهٔ زمان‌بندی‌شدهٔ Food Ticket PHP Worker را می‌سازد و بلافاصله شروع می‌کند. اگر PHP در PATH یا مسیر پیش‌فرض XAMPP باشد، آرگومان دوم ممکن است لازم نباشد.

تأیید، فعال‌سازی و چاپ آزمایشی

Task Scheduler را باز کنید و در Task Scheduler Library وضعیت Food Ticket PHP Worker را ببینید. نصب‌گر وظیفه را برای حساب فعلی و هنگام ورود همان حساب تنظیم می‌کند؛ آن حساب باید در Windows وارد بماند. سپس تنظیمات را دوباره بررسی و Worker را از پنل فعال کنید.

پیش از فعال‌سازی، ترددهای امروز در SOURCE_TABLE را مرور کنید؛ Worker ممکن است آن‌ها را پردازش کند. دکمهٔ تست اتصال/چاپ یک فیش نمونه به چاپگر می‌فرستد و واقعاً کاغذ چاپ می‌کند. وضعیت Worker را در بخش پایش بررسی کنید.

خلاصهٔ دانلود: روی سروری که سامانه هم‌اکنون فعال است، معمولاً دانلود PHP، MySQL، PowerShell یا XAMPP لازم نیست. فقط در صورت نبودن Access ODBC/ACE، Microsoft 365 Access Runtime را نصب کنید؛ درایور چاپگر هم فقط برای صف چاپ Windows لازم است. برای این روش .NET یا Worker سرویس C# لازم نیست.

بستهٔ فایل‌های لازم از پروژه

این بسته فقط شامل Migration و دو فایل نصب‌گر است؛ خود سامانه و کد Worker را جایگزین نمی‌کند. فایل‌ها را در ریشهٔ برنامه با همان ساختار پوشه‌ای قرار دهید.

فایل food-ticket-worker-install-files.zip کنار این راهنما قرار دارد؛ فایل‌های آن را با حفظ ساختار پوشه‌ها در ریشهٔ برنامه استخراج کنید.
