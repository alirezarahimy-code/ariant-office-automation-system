سامانه پشتیبانی فارسی - بسته کامل نصب

این بسته مستقل است و نیازی به کپی‌کردن config.php یا storage از نسخه قبلی ندارد.

مراحل نصب در XAMPP:

1. از دیتابیس قبلی backup بگیرید؛ اگر می‌خواهید پیوست‌ها یا لوگوها را نگه دارید، `storage/uploads` و `assets/uploads` را هم جداگانه کپی کنید.
2. فولدر قبلی سامانه را حذف کنید.
3. محتویات این بسته را داخل htdocs و در فولدر persian-ticketing استخراج کنید.
4. از همان رایانهٔ سرور در مرورگر باز کنید:
   http://localhost/persian-ticketing/install.php
5. در مرحله اتصال MySQL، برای نصب تمیز نام دیتابیس جدید وارد کنید:
   persian_ticketing_clean
6. مراحل نصب را تا پایان ادامه دهید. config.php و جدول‌های نهایی خودکار ساخته می‌شوند.
7. پس از ورود مدیر، در «تنظیمات» ابتدا نگاشت گروه‌های AD را ذخیره کنید و سپس روی «همگام‌سازی همه کاربران دامین» بزنید.
8. برای تعیین مدیر سامانه یا ادمین اصلی دیگر، از «تنظیمات» به بخش «کاربران» بروید؛ نقش «مدیر سامانه» را انتخاب کنید و تیک «ادمین اصلی» را بزنید. فقط ادمین اصلی فعلی می‌تواند این تغییر را ذخیره کند.

اگر از دیتابیس نسخهٔ قبلی استفاده می‌کنید:
- فایل‌های `upgrade-1.1-departments.sql` تا `upgrade-1.11-user-profile.sql` را به‌ترتیب و هرکدام فقط یک‌بار روی همان دیتابیس اجرا کنید.
- برای خطای صفحات «گزارش‌ها» یا «تغییر و مشکل»، حداقل Migrationهای `upgrade-1.2-itsm.sql`، `upgrade-1.7-governance.sql` و `upgrade-1.8-routing.sql` باید اجرا شده باشند.
- اگر می‌خواهید نصب کاملاً تمیز داشته باشید، از دیتابیس قبلی backup بگیرید و در نصب نام دیتابیس جدید وارد کنید؛ در این حالت نیازی به اجرای Upgradeها نیست.
- در فرم نصب (مرحلهٔ ۱) گزینهٔ «حذف پایگاه‌داده موجود با همین نام و ساخت از نو» وجود دارد. با فعال‌کردن آن، نام پایگاه‌داده را دوباره تایپ کنید؛ دیتابیس هم‌نام قبلی هنگام نصب کاملاً حذف و از نو ساخته می‌شود.

نکات:
- برای نصب تمیز از نام دیتابیس جدید استفاده کنید تا فیلدهای نسخه قبلی باقی نمانند.
- اگر `config.php` یا `installed.lock` از نصب قبلی موجود است، فقط پس از backup از دیتابیس و پیوست‌ها و از روی خود سرور `install.php?force=1` را باز کنید. گزینه حذف دیتابیس را فقط برای پاک‌کردن قطعی همهٔ داده‌های آن انتخاب کنید؛ نام دیتابیس باید دوباره تایپ شود و دیتابیس‌های سیستمی محافظت شده‌اند. برای نگه‌داشتن داده‌ها از دستورالعمل ارتقا استفاده کنید.
- نام کاربری معمول XAMPP برابر root و رمز آن معمولاً خالی است، مگر اینکه تغییر داده باشید.
- اتصال واقعی Access و چاپگر فیش غذا بعد از نصب از صفحه «چاپ فیش غذا» تنظیم می‌شود.
- صفحه «پروفایل کاربری» برای ثبت نام، نام خانوادگی، کد ملی و عکس در منوی بالای سامانه اضافه شده است.
- نام و لوگوی مستقل پنل چاپ فیش از بخش «تنظیمات ← هویت پنل چاپ فیش غذا» قابل تغییر است.
- چاپ فیش در نسخهٔ فعلی داخل همین سامانه و مسیر `index.php?page=food-ticket` انجام می‌شود؛ برای گزارش‌گیری نیازی به بازکردن آدرس یا پنل جداگانه نیست.
- برای اجرای خودکار PHP Worker هنگام ورود Windows، فایل `tools/install_food_ticket_worker_windows.bat` را با همان حساب دارای دسترسی به Access و چاپگر اجرا کنید. PHP CLI همان مسیر باید `pdo_mysql` و `openssl` داشته باشد و تابع `exec` آن غیرفعال نباشد. برای PHP مستقل، مسیر `php.exe` را به نصب‌گر بدهید. این Task فقط در نشست همان حساب کار می‌کند و کاربر باید وارد Windows بماند.
- پس از نصب پردازشگر، لینک «چاپ فیش غذا» در منوی اصلی همان صفحهٔ سامانه را باز می‌کند. اجرای `food-ticket-web/start_food_ticket.bat` برای این روش لازم نیست.
- دسترسی فرم چاپ فیش فقط برای ادمین اصلی و مدیر پشتیبانی فعال است؛ ادمین اصلی همهٔ زیرفرم‌ها را می‌بیند و مدیر پشتیبانی فقط داشبورد، پایش، سفارش‌های غذا، کارکنان و گزارش‌ها را دارد.
- دکمه‌های انتخاب فایل/پوشهٔ Windows در «تنظیمات ← اتصال پایگاه‌ها» فقط برای ادمین اصلی فعال‌اند و سرویس `food-ticket-web` باید روی Windows Server به‌صورت تعاملی اجرا شود.
- برای نصب‌های قدیمی، `upgrade-1.9-food-ticket.sql` را در صورت نبود جداول ماژول و سپس `upgrade-1.19-food-ticket-queue.sql` را اجرا کنید.
- اگر مسیر Access یا سفارش روی شبکه است، از UNC path استفاده کنید و دسترسی را به همان حساب Windows اجرای Worker بدهید.
- همگام‌سازی کاربران دامین به حساب سرویس LDAP با دسترسی خواندن نیاز دارد؛ می‌توانید آن را از تنظیمات یا Task Scheduler اجرا کنید.
- فایل rebuild-final.sql فقط برای بازسازی مخرب دیتابیس موجود است و برای نصب معمول لازم نیست.

--- اسکن دامنه (استخراج کامپیوترهای آنلاین از شبکه) ---
1) upgrade-1.20-domain-scan.sql را یک‌بار اجرا کنید.
2) در تنظیمات → تب «اسکن دامنه»، دامنه و حساب ادمین را وارد و فعال کنید.
3) از منوی «اسکن دامنه» دکمهٔ شروع را بزنید، یا برای تعداد زیاد:
   php cron/domain_scan_worker.php --loop
4) پینگ دستی: در «شناسنامه‌های فنی سیستم»، سیستم‌ها را تیک بزنید (یا «انتخاب همه»)
   و دکمهٔ «پینگ سیستم‌های انتخابی» را بزنید. وضعیت آنلاین/آفلاین هر سیستم با پینگ
   موازی به‌روزرسانی می‌شود.

امنیت: پس از نصب، install.php را حذف یا از دسترس خارج کنید.
چاپ فیش: فقط یکی از موتورهای PHP worker یا سرویس C# را فعال کنید (نه هر دو با هم).

--- Worker پس‌زمینه چاپ فیش (الزامی برای استقلال از Browser) ---
1) اگر جداول ماژول فیش ساخته نشده‌اند: mysql < upgrade-1.9-food-ticket.sql
2) mysql < upgrade-1.19-food-ticket-queue.sql
2.1) یک‌بار upgrade-1.27-food-ticket-fixes.sql را اجرا کنید (پاکسازی printer_mode قدیمی windows_queue).
3) php tests/test_food_ticket_logic.php
4) ویندوز: tools\install_food_ticket_worker_windows.bat (با همان حساب کاربری دارای دسترسی به Access/چاپگر)
5) برای چاپگر شبکه‌ای: printer_mode = tcp_raw و IP:9100 (نه windows_share مگر صف ویندوز واقعاً لازم باشد).
6) سرویس C# (food-ticket-web) را همزمان با PHP Worker روشن نکنید.
   یا دستی: php cron\food_ticket_worker.php --loop
5) فقط Worker PHP را فعال کنید؛ سرویس C# را همزمان روشن نکنید.
6) تنظیم چاپگر حرارتی ۸۰ میلی‌متری: IP:9100 یا نام صف ویندوز در تنظیمات فیش.
