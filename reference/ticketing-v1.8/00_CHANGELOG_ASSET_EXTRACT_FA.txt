بازبینی و اصلاح بخش «استخراج شناسنامه»
=========================================
تاریخ: 1405 (نسخه Food Ticket UI v3.4)

ایرادهای پیداشده و رفع‌شده:

۱) داده‌های سرور روی سیستم‌های کلاینت نوشته می‌شد (خطای جدی)
   - قبلاً اگر برای یک کلاینت هیچ snapshot سخت‌افزاری نبود، سیستم اطلاعات سرور را
     جمع می‌کرد و در شناسنامه همان کلاینت ذخیره می‌کرد.
   - حالا استخراج از سرور فقط برای خودِ سیستم سرور (asset_tag با SERVER- یا
     هم‌نامی با hostname سرور) انجام می‌شود؛ برای کلاینت فقط snapshot خودش.

۲) snapshot بی‌سخت‌افزار، snapshot سخت‌افزاری را پنهان می‌کرد
   - قبلاً فقط آخرین snapshot خوانده می‌شد و استخراج چیزی نمی‌یافت.
   - حالا تا ۵۰ snapshot اخیر بررسی و از اولین snapshot دارای سخت‌افزار
     (ترجیحاً دارای هارد) استفاده می‌شود.

۳) ورود هر کاربر، hardware_json کلاینت را پاک می‌کرد (خطای جدی)
   - در inventory_collect_client_asset، در هر ورود، hardware_json با یک JSON
     کوچک شناسه (IP/User-Agent) بازنویسی می‌شد و اطلاعات کامل Agent از بین می‌رفت.
   - حالا اگر سخت‌افزار کامل وجود داشته باشد بازنویسی نمی‌شود، و snapshot شناسه
     فقط یک‌بار (وقتی هیچ تاریخچه‌ای نیست) ثبت می‌شود.

۴) استخراج، مقادیر دستی را پاک می‌کرد
   - حالا به‌صورت پیش‌فرض فقط فیلدهای خالی پر می‌شوند.
   - برای بازنویسی عمدی، چک‌باکس «بازنویسی مقادیر موجود» کنار دکمهٔ استخراج اضافه شد.

۵) جمع‌آوری سرور با ۱۹ پروسهٔ PowerShell جداگانه (کند و شکننده)
   - همهٔ کوئری‌ها به یک اسکریپت واحد منتقل شد:
     tools/collect_server_inventory.ps1
   - یک پروسه، ExecutionPolicy Bypass، خروجی JSON واحد، و ثبت پیام خطا.

۶) خطاهای جمع‌آوری بی‌صدا نادیده گرفته می‌شدند
   - حالا آخرین خطا (inventory_last_error) ثبت و به کاربر نشان داده می‌شود؛
     صفحهٔ «تست جمع‌آوری» تعداد اقلام برگشته را نمایش می‌دهد.

۷) انتخاب IP اشتباه
   - قبلاً اولین آداپتور شبکه انتخاب می‌شد (ممکن بود آداپتور مجازی/VPN باشد).
   - حالا IP اصلی سرور ترجیح داده می‌شود، بعد اولین IPv4 معتبر غیر APIPA.

۸) نوع رایانهٔ سرور اشتباه
   - قبلاً روی سرور «Windows client» نوشته می‌شد؛ حالا «Windows Server».

۹) رفع TypeError هنگام نبودن آداپتور/دیسک (دسترسی به آرایهٔ خالی).

نکتهٔ مهم برای کلاینت‌ها:
   استخراج سخت‌افزار هر کامپیوتر فقط وقتی کامل می‌شود که Agent روی خودِ آن
   کامپیوتر اجرا شود و از طریق api/inventory.php اطلاعات را بفرستد.

اصلاح دوم — فقط سیستمِ میزبان پنل
==================================
- دکمهٔ «برداشت اطلاعات سرور» حذف و به «استخراج اطلاعات این سیستم» تغییر نام یافت.
- دکمهٔ «استخراج از سیستم» از صفحهٔ شناسنامهٔ سایر سیستم‌ها حذف شد؛
  فقط روی شناسنامهٔ همین کامپیوتر (میزبان پنل) نمایش داده می‌شود.
- اکشن قدیمی extract_asset_profile که می‌توانست روی هر سیستم اجرا شود حذف شد.
- بررسی میزبانی بر اساس asset_tag = SERVER-<hostname> همین دستگاه یا هم‌نامی hostname.
- ثبت هویت خودکار کلاینت هنگام ورود، دیگر برای خودِ کامپیوتر میزبان (127.0.0.1/::1)
  یک شناسنامهٔ تکراری ایجاد نمی‌کند.
- برای سیستم‌های غیرمیزبان، فقط پیام راهنما نمایش داده می‌شود (نیاز به Agent روی همان سیستم).

نتیجه: استخراج خودکار فقط برای همان کامپیوتری انجام می‌شود که پنل روی آن اجرا شده است.
