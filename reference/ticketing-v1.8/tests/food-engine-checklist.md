# چک‌لیست نهایی موتور چاپ فیش غذا

## ۱. پیش‌نیاز سرور

- سرویس C# (.NET) حذف شده است؛ موتور پایش فقط PHP Worker است.
- Microsoft Access Database Engine متناسب با معماری Windows نصب باشد.
- چاپگر شبکه در Windows به‌صورت اشتراکی نصب شده باشد.
- دسترسی شبکه به فایل منبع تردد (TENTER/Access) برقرار باشد. سفارش غذا از دیتابیس داخلی خوانده می‌شود.

## ۲. راه‌اندازی

1. Worker را طبق `tools/install_food_ticket_worker.ps1` یا `install-food-worker-SERVICE.bat` به‌عنوان سرویس نصب کنید.
2. پنل را از `index.php?page=food-ticket` باز کنید.

## ۳. تنظیمات اتصال

- مسیر منبع تردد (فایل Access)، نام جدول و ستون‌های `L_UID`, `C_Card`, `C_Date`, `C_Time`.
- مسیر فایل سفارش غذا و نام جدول سفارش.
- نام چاپگر نصب‌شده و روش چاپ (`صف چاپگر Windows`).
- مسیر خروجی Excel.

## ۴. آزمون کامل موتور چاپ

از منوی «تنظیمات» → «سلامت سیستم» دکمهٔ «آزمون کامل موتور چاپ» را بزنید. این آزمون به‌صورت واقعی بررسی می‌کند:

- دیتابیس داخلی مانیتورینگ: قابل خواندن و نوشتن باشد.
- منبع تردد (SOURCE_TABLE): قابل خواندن باشد.
- سفارش غذا: قابل خواندن باشد.
- کارکنان: جدول کارکنان خوانده شود.
- چاپگر: یک فیش آزمایشی واقعی ارسال شود.

اگر همهٔ موارد «سالم» شدند، موتور آمادهٔ کار است.

## ۷. آزمون مسیر جایگزین PHP Worker

این مسیر را به‌جای سرویس C# انتخاب کنید؛ اجرای هم‌زمان هر دو ممنوع است.

- روی Windows مقصد، افزونه‌های `pdo_mysql` و `openssl` را برای PHP CLI فعال کنید، تابع `exec` را بررسی کنید و دسترسی همان حساب را به MySQL، فایل‌های Access و چاپگر بسنجید. برای Access، افزونهٔ PHP `odbc` یا fallback پاورشل/ACE لازم است.
- دیتابیس اصلی را با `upgrade-1.9-food-ticket.sql` و سپس `upgrade-1.19-food-ticket-queue.sql` ارتقا دهید.
- اجرا کنید: `tools\install_food_ticket_worker_windows.bat C:\xampp\php\php.exe`. این کار برای حساب Windows فعلی یک Scheduled Task می‌سازد؛ حساب باید هنگام کار Worker وارد سیستم بماند.
- در پنل اصلی، اتصال منبع تردد، سفارش‌ها و چاپگر را آزمایش و پردازش را فعال کنید؛ سپس وضعیت و پیام آخر Worker را بررسی کنید.
- کارت آزمایشی را یک‌بار بزنید: رویداد باید در پایگاه مانیتورینگ و صف چاپ ثبت شود و سپس همان ردیف SOURCE_TABLE با تطبیق دقیق حذف شود؛ خطای چاپ باید در مانیتورینگ باقی بماند تا از همان رویداد دوباره چاپ شود. سرویس چاپ تضمین خروج فیزیکی کاغذ را ارائه نمی‌کند و فقط پذیرش موفق داده توسط چاپگر را می‌سنجد.
- اجرای `php tests/test_food_ticket_logic.php` و `php tests/smoke.php` باید قبل از آزمون مقصد موفق شود.

## ۵. چرخهٔ روزانه

1. کارت کارکنان روی دستگاه تردد خوانده می‌شود و رکورد در SOURCE_TABLE ثبت می‌شود.
2. سرویس هر چند ثانیه SOURCE_TABLE را می‌خواند.
3. کد پرسنلی با کارکنان تطبیق داده می‌شود.
4. سفارش غذای همان روز خوانده می‌شود.
5. نتیجه در مانیتورینگ محلی ثبت می‌شود.
6. فیش به چاپگر ارسال می‌شود.
7. پس از ثبت پایدار رویداد و صف/نتیجه در سامانه، همان ردیف منبع از SOURCE_TABLE حذف می‌شود؛ تلاش‌های چاپ مجدد از رویداد ذخیره‌شده انجام می‌شوند.

## ۶. اگر چاپ خطا خورد

- رکورد در مانیتورینگ با وضعیت «خطای چاپ» باقی می‌ماند.
- از «گزارش‌ها» → «چاپ مجدد خطاهای واقعی» می‌توانید همه را دوباره چاپ کنید.
- اگر خود سرویس قطع شود، پس از راه‌اندازی دوباره، صف باقی‌ماندهٔ مانیتورینگ خودکار پردازش می‌شود.
