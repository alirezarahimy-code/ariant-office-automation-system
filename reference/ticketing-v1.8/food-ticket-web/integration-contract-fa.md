# قرارداد اتصال به سامانه اصلی

## وضعیت فعلی

سرویس در حالت ورود مدیر محلی قرار دارد و بدون ورود باز نمی‌شود؛ رمز واقعی در بسته تعیین نشده است و باید در `food_ticket_config.json` روی سرور تنظیم شود. ورود SSO از سامانه اصلی نیز پشتیبانی می‌شود. داده‌های مانیتورینگ و مدیریت محلی در SQLite سرویس‌اند و این پیاده‌سازی به MySQL سامانه اصلی متصل نیست.

## رفتار نهایی

1. کاربر در سامانه اصلی وارد می‌شود.
2. سامانه اصلی نقش کاربر را مشخص می‌کند.
3. با انتخاب «سیستم چاپ فیش»، token امضاشدهٔ سامانهٔ اصلی به endpoint سرویس تحویل می‌شود.
4. اگر نقش `admin` یا `support` باشد، پنل بدون ورود دوباره باز می‌شود.
5. اگر نقش یا امضا معتبر نباشد، سرویس دسترسی را رد می‌کند.
6. نام کاربری و رمز در آدرس صفحه، LocalStorage یا کد HTML قرار نمی‌گیرد.

## اطلاعات لازم از سامانه اصلی

- شناسه کاربر جاری
- نقش کاربر: `admin`، `support` یا `user`
- آدرس برگشت به سامانه اصلی
- روش امضای نشست یک‌بارمصرف، ترجیحاً HMAC بین دو سرویس
- token باید شامل `role`، `service_group`، `user_id` و `exp` باشد و با HMAC-SHA256 کلید `app.key` امضا شود.

نشست پس از SSO در حافظهٔ سرویس نگه‌داری می‌شود و تا ۸ ساعت اعتبار دارد. برای نشست‌های یک‌بارمصرف و کوتاه‌مدت یا اتصال مانیتورینگ به MySQL باید تغییر جداگانه انجام شود.
