سند میراثی برای موتور قدیمی Access/C# است و دستورهای آن برای ماژول جاری قابل اجرا نیست. نسخهٔ جاری سفارش را از MySQL داخلی می‌خواند؛ Access تردد TENTER باقی است. برای نصب و rollback ماژول فعلی، راهنمای عملیاتی 1.38 را ببینید. Worker قدیمی C# را اجرا نکنید.

نصب کامل سامانه و Worker چاپ فیش غذا

راهنمای بستهٔ یکپارچه · لینک‌های رسمی بررسی‌شده در ۳۰ سپتامبر ۲۰۲۶

این ZIP شامل کد کامل سامانه، Worker چاپ فیش، migrationها، نصب‌گر Windows و این راهنماست. برنامه‌های خارجی مثل PHP/XAMPP، Access Runtime و درایور چاپگر به‌علت تفاوت نسخه و مجوز، داخل بسته نیستند و لینک رسمی آن‌ها پایین آمده است.

هشدار مهم: برای راه‌اندازی از صفر، از یک نام دیتابیس جدید و خالی استفاده کنید. گزینهٔ «حذف پایگاه‌دادهٔ موجود» را فعال نکنید مگر عمداً می‌خواهید تمام اطلاعات آن دیتابیس پاک شود. فایل rebuild-final.sql مخرب است؛ در نصب عادی آن را اجرا نکنید.

پیش‌نیازها و دانلودها

محیط اجرا: XAMPP برای تست و شبکهٔ داخلی کوچک

XAMPP یکجا Apache، PHP، MariaDB و phpMyAdmin را فراهم می‌کند. اگر این سامانه را روی سرور موجود نصب می‌کنید، XAMPP دوم نصب نکنید. صفحهٔ رسمی هنگام بررسی نسخه‌های قدیمی Windows را نشان می‌داد؛ پیش از نصب، نسخهٔ PHP را بررسی کنید و برای سرور تولیدی از نسخهٔ به‌روز و تأییدشدهٔ سازمان استفاده کنید.

دانلود رسمی XAMPP

PHP CLI الزامی

PHP نسخهٔ ۸٫۱ یا جدیدتر لازم است. در XAMPP، فایل CLI معمولاً C:\xampp\php\php.exe است. اگر فقط CLI ندارید، نسخهٔ NTS x64 برای فرمان‌های PHP مناسب است؛ نصب PHP جدا وب‌سرور ایجاد نمی‌کند.

صفحهٔ رسمی PHP 8.4 Windowsدانلود مستقیم PHP 8.4.26 x64 NTSVisual C++ Runtime x64 (اگر درخواست شد)

افزونه‌های PHP لازم برای اجرا

pdo_mysql برای اتصال برنامه به MySQL/MariaDB و openssl برای بازکردن رمز Access ذخیره‌شده لازم‌اند؛ تابع exec نیز نباید در disable_functions مسدود باشد. در همان PHP CLI بررسی کنید. ldap فقط برای ورود/همگام‌سازی Active Directory لازم است. ODBC برای Access اختیاری است اگر ACE/OLEDB از PowerShell استفاده شود.

Microsoft Access Runtime فقط اگر Access ODBC آماده نیست

Worker می‌تواند از PHP ODBC یا PowerShell همراه Access Database Engine استفاده کند. اگر Runtime نصب می‌کنید، معماری ۳۲/۶۴ بیت را با Office نصب‌شده تطبیق دهید. Microsoft 365 Access Runtime با Office نصب‌شده از Windows Installer سازگار نیست؛ در چنین سروری اول با مدیر سیستم هماهنگ کنید.

راهنمای رسمی Runtime و انتخاب معماریدریافت مستقیم Runtime انگلیسی x64

PowerShell و Task Scheduler داخل Windows

Windows Server 2016 و جدیدتر معمولاً Windows PowerShell 5.1 و Task Scheduler را دارند؛ فایل نصب‌گر PHP Worker به powershell.exe نیاز دارد. PowerShell 7 یا .NET برای مسیر PHP لازم نیست.

مستند Microsoft دربارهٔ Windows PowerShell 5.1

درایور چاپگر فقط برای صف Windows

اگر چاپ با صف Windows است، درایور را نصب کنید. درایور رسمی سازندهٔ چاپگر یا درایور عمومی فیش‌پرینتر ۸۰ میلی‌متری را نصب کنید و تطابق آن را بررسی کنید. چاپ شبکه‌ای RAW روی پورت ۹۱۰۰ ممکن است بدون درایور Windows انجام شود.

راه‌اندازی از ابتدا

آماده‌کردن Windows و سرویس‌ها

برای تست، XAMPP را از سایت رسمی نصب کنید و در XAMPP Control Panel، Apache و MySQL را Start کنید. برای تولید، از Windows Server و نسخه‌های به‌روز سازمانی استفاده کنید. در PHP باید pdo_mysql فعال باشد؛ برای Worker، exec نیز فعال باشد.

تنظیم PHP CLI مستقل (فقط اگر PHP سرور را استفاده نمی‌کنید)

اگر PHP 8.4.26 NTS x64 را به‌شکل ZIP دانلود کرده‌اید، آن را در C:\php84 استخراج کنید و بررسی کنید C:\php84\php.exe وجود دارد. از php.ini-production کنار آن یک کپی با نام php.ini بسازید:

copy C:\php84\php.ini-production C:\php84\php.ini

در C:\php84\php.ini مسیر افزونه‌ها را تنظیم و افزونه‌های موردنیاز را فعال کنید؛ اگر خطی از قبل هست همان را ویرایش کنید و خط تکراری نسازید:

extension_dir = "C:\php84\ext" extension=pdo_mysql extension=openssl

در Command Prompt بررسی کنید که فایل تنظیمات همین PHP بارگذاری شده و نیازمندی‌ها آماده‌اند. خروجی باید pdo_mysql OK، openssl OK و exec OK داشته باشد. این PHP مستقل تنظیمات PHP داخل XAMPP/Apache را تغییر نمی‌دهد.

"C:\php84\php.exe" --ini "C:\php84\php.exe" -r "echo extension_loaded('pdo_mysql') ? 'pdo_mysql OK' : 'pdo_mysql MISSING', PHP_EOL; echo extension_loaded('openssl') ? 'openssl OK' : 'openssl MISSING', PHP_EOL; echo function_exists('exec') ? 'exec OK' : 'exec MISSING', PHP_EOL;"

استخراج بسته در محل درست

یک پوشهٔ خالی به نام C:\xampp\htdocs\persian-ticketing بسازید و محتوای ZIP کامل را داخل همان پوشه استخراج کنید؛ فایل install.php باید مستقیماً در ریشهٔ پوشه باشد، نه داخل یک پوشهٔ اضافی. بهتر است مسیر نصب Windows فاقد نام فارسی باشد.

اجرای نصب‌کنندهٔ وب سامانه

روی همان سرور در مرورگر باز کنید:

http://localhost/persian-ticketing/install.php

گام ۱: نام سامانه و اطلاعات MySQL/MariaDB را وارد کنید. برای شروع از دیتابیس جدید و خالی مثل persian_ticketing استفاده کنید، اتصال را تست کنید و ادامه دهید. کاربر دیتابیس باید اجازهٔ ساخت دیتابیس و جدول‌ها را داشته باشد.

گام ۲: اگر Active Directory آماده نیست، اتصال LDAP را خاموش بگذارید و ادامه دهید؛ بعداً از تنظیمات قابل تکمیل است. گام ۳: حساب ادمین اصلی و رمز حداقل ۸ کاراکتری بسازید. نصب‌کننده فایل schema.sql را اجرا و config.php و پوشه‌های لازم را می‌سازد.

ایمن‌کردن نصب تازه

پس از ورود، بررسی کنید صفحه‌های سامانه باز می‌شوند. install.php را از دسترس وب خارج یا حذف کنید و سایت عملیاتی را پشت HTTPS نگه دارید. رمز MySQL را در فایل نمونه یا پیام ارسال نکنید.

تکمیل تنظیمات چاپ فیش

در منوی «چاپ فیش غذا»، فایل منبع تردد، فایل سفارش، نام جدول سفارش و روش چاپگر را وارد کنید. اگر فایل Access روی اشتراک شبکه است از مسیر UNC استفاده کنید. Worker را تا پایان نصب و بررسی اولیه خاموش نگه دارید.

نصب Worker PHP

روی همان Windows و با حسابی وارد شوید که به فایل‌های Access، MySQL و چاپگر دسترسی دارد. Command Prompt را باز کنید و مسیرها را مطابق سرور خود عوض کنید:

"C:\xampp\htdocs\persian-ticketing\tools\install_food_ticket_worker_windows.bat" "C:\xampp\php\php.exe"

اگر از PHP مستقل استفاده می‌کنید، آرگومان دوم را C:\php84\php.exe بگذارید. نصب‌گر PHP CLI، افزونه‌های pdo_mysql و openssl و تابع exec را بررسی می‌کند و وظیفهٔ Food Ticket PHP Worker را می‌سازد. در Task Scheduler وجود وظیفه و وضعیت اجرا را بررسی کنید. حساب Windows باید در زمان کار Worker وارد بماند.

آزمون نهایی

ابتدا مسیرها و تنظیمات چاپگر را دوباره مرور کنید، سپس Worker را از پنل فعال کنید. پیش از فعال‌سازی، رکوردهای امروز SOURCE_TABLE را بررسی کنید؛ Worker ممکن است آن‌ها را پردازش کند. تست چاپ، واقعاً یک برگهٔ نمونه چاپ می‌کند. وضعیت آخرین فعالیت را از بخش پایش Worker ببینید.

مهم دربارهٔ Migration: در نصب تازه، install.php از schema.sql استفاده می‌کند و جدول‌های صف ۱٫۱۹ را هم می‌سازد؛ پس Migrationهای قدیمی را دستی اجرا نکنید. فایل ۱٫۱۹ برای ارتقای دیتابیس موجود است. اگر سامانهٔ قبلی دارید، از دیتابیس پشتیبان بگیرید و مسیر ارتقا را طبق نسخهٔ فعلی دنبال کنید؛ نصب تازه را روی دیتابیس حاوی اطلاعات اجرا نکنید.

فایل‌های داخل بسته

در ZIP کامل، همهٔ فایل‌های سامانه در ریشه قرار دارند. فایل‌های اصلی Worker در cron\food_ticket_worker.php و tools\install_food_ticket_worker_windows.bat هستند. ZIP کمکی food-ticket-worker-install-files.zip و راهنمای جداگانهٔ Worker نیز در بسته آمده‌اند. سرویس C# قدیمی هم در پوشهٔ food-ticket-web باقی است، اما در این نصب PHP آن را اجرا نکنید؛ دو Worker نباید هم‌زمان فعال شوند.
