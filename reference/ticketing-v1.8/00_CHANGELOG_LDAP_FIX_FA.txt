رفع و تشخیص اتصال دامنه (LDAP/AD) — v3.4
==========================================

مشکل گزارش‌شده: «اتصال به دامنه کار نمی‌کند و کاربران ایمپورت نمی‌شوند.»

علت اصلی: دکمهٔ «همگام‌سازی همه کاربران دامین» و «ذخیره تنظیمات دامین» فرم‌های POST هستند و
پیش از اصلاح CSRF (فاز قبل) با خطای ۴۱۹ «درخواست نامعتبر» رد می‌شدند؛ به همین دلیل کاربران
ایمپورت نمی‌شدند. اصلاح CSRF این مورد را هم حل می‌کند.

اصلاحات این فاز:
۱) دکمهٔ «تشخیص اتصال دامنه» در تنظیمات (aciton=diagnose_ldap) + تابع ldap_diagnose() که
   گام‌به‌گام بررسی می‌کند: افزونه LDAP، فعال بودن، آدرس کنترلر، Base DN، اتصال، bind
   ناشناس/حساب سرویس و جست‌وجو؛ و پیام دقیق خطا نشان می‌دهد.

۲) ابزار خط فرمان tools/diagnose_ldap.php برای تشخیص سریع روی سرور.

۳) صفحه‌بندی LDAP برای PHP 8.4+:
   در PHP >= 8.4 تابع ldap_control_paged_result حذف شده و صفحه‌بندی از کار می‌افتاد.
   اکنون با LDAP controls و ldap_parse_result انجام می‌شود و با PHP قدیمی هم سازگار است.

۴) Base DN اختیاری شد: اگر خالی باشد، از defaultNamingContext دامین کشف می‌شود.
   پیام‌های خطای دقیق‌تر برای bind ناشناس و bind ناموفق حساب سرویس اضافه شد.

نکتهٔ محیطی مهم برای مدیر شبکه:
- افزونهٔ php-ldap باید روی وب‌سرور نصب/فعال باشد (ویندوز: extension=ldap در php.ini،
  لینوکس: php-ldap). اگر نباشد، هیچ اتصال دامنه‌ای ممکن نیست.
- حساب سرویس با دسترسی خواندن Base DN بهتر است ثبت شود؛ بسیاری از کنترلرها bind ناشناس را
  رد می‌کنند.
- برای LDAPS پورت 636 و گاهی نصب گواهی کنترلر لازم است.
