راهنمای نصب نسخهٔ ۱.۳۲ — نمایندهٔ گروه با L_UID + غیبت روزانه + تحویل غذا
================================================================================

پیش‌نیاز: همان پیش‌نیازهای فعلی سامانه (PHP 8.x با pdo_mysql، MySQL/MariaDB، اپاچی یا IIS).
هیچ کتابخانه/سرویس تازه‌ای لازم نیست.

────────────────────────────────────────────────────────────────────────────────
۰) بکاپ (اجباری)
────────────────────────────────────────────────────────────────────────────────
- بکاپ کامل دیتابیس:  mysqldump -u USER -p DBNAME > backup-before-1.32.sql
- بکاپ پوشهٔ سایت (حداقل پوشهٔ ticket و فایل config.php).

────────────────────────────────────────────────────────────────────────────────
۱) اعمال فایل‌ها (سه راه؛ هر کدام را خواستید)
────────────────────────────────────────────────────────────────────────────────
راه الف — پچ (کم‌ریسک‌ترین؛ اگر مخزن git دارید):
    git apply -p1 /مسیر/patch-1.32.diff
    (یا:  patch -p1 < patch-1.32.diff )

راه ب — کپی فایل‌های تغییر‌یافته (overlay):
    پوشهٔ 01-overlay/ticket/ را روی ریشهٔ پروژه کپی کنید (۱۱ فایل تغییر‌یافته + ۴ فایل جدید).
    ⚠️ فایل .htaccess و .env.example در این پوشه نیستند تا تنظیمات واقعی سرور شما دست‌نخورده بماند.

راه ج — جایگزینی کل درخت (درخت آماده):
    پوشهٔ 02-full/ticket/ کل پروژهٔ آماده است. اگر این راه را انتخاب می‌کنید:
      • فایل config.php سرور خودتان را نگه دارید (در بسته نیست).
      • اگر سرور شما .htaccess اختصاصی دارد، آن را با نسخهٔ بسته عوض نکنید.
      • فایل‌های دودویی که در دامپ متنی نبودند (assets/fonts/*.woff2،
        worker-install.zip، *.csproj، run-food-worker-service.cmd،
        .github/workflows/ci.yml، Program.cs) باید از نسخهٔ سرور خودتان بمانند.

────────────────────────────────────────────────────────────────────────────────
۲) مهاجرت دیتابیس
────────────────────────────────────────────────────────────────────────────────
    mysql -u USER -p DBNAME < ticket/upgrade-1.32-food-group-representative-absence.sql
- همهٔ تغییرات افزایشی‌اند: ADD COLUMN / ADD UNIQUE KEY / MODIFY rfid_card → NULL /
  CREATE TABLE IF NOT EXISTS. هیچ داده‌ای حذف یا بازنویسی نمی‌شود.
- اگر این فایل را اجرا نکنید، کد در اولین اجرا خودش ستون‌ها/جدول‌های لازم را
  (به‌صورت محافظت‌شده) می‌سازد؛ اجرای دستی برای Production توصیه می‌شود.
- Rollback: بخش انتهای همان فایل SQL (به‌ترتیب معکوس).

────────────────────────────────────────────────────────────────────────────────
۳) تنظیم گروه‌ها (یک‌بار برای هر گروه)
────────────────────────────────────────────────────────────────────────────────
پنل → تنظیمات → گروه‌های غذا → «ویرایش گروه»:
  • «L_UID نمایندهٔ گروه» را وارد کنید (همان شناسه‌ای که دستگاه حضور و غیاب برای نماینده
    می‌فرستد؛ همان L_UID ردیف SOURCE_TABLE).
  • فیلد کارت RFID فقط برای گروه‌های قدیمی است؛ برای گروه‌های جدید خالی بگذارید.
  • اگر L_UID وارد‌شده کد پرسنلی کاربری باشد که عضو این گروه نیست، سامانه با پیام روشن
    جلوگیری می‌کند (تا فیش کارمند عادی خراب نشود).
  • تعداد فیش را وارد نکنید؛ سامانه محاسبه می‌کند.

ثبت غیبت روزانه: همان صفحه → دکمهٔ «غیبت امروز» → تیک اعضای غایب → «ذخیرهٔ غیبت این تاریخ».
  تا نخستین تردد معتبر نماینده قابل ویرایش است؛ بعد از آن برچسب 🔒 قفل شده می‌خورد و
  اصلاح فقط با نقش مجاز + «دلیل» + ثبت در Audit انجام می‌شود.

────────────────────────────────────────────────────────────────────────────────
۴) دسترسی‌ها (اختیاری)
────────────────────────────────────────────────────────────────────────────────
- مجوز جدید: food.groups_override («اصلاح غیبت بعد از قفل شدن») — به‌صورت پیش‌فرض برای
  supervisor و support_manager در نظر گرفته شده و primary_admin همه‌چیز را دارد.
  اگر می‌خواهید فقط با تیک صریح باشد، در ماتریس نقش‌ها تنظیم کنید.

۵) آزمون پس از نصب
────────────────────────────────────────────────────────────────────────────────
    php tools/test_group_flow_offline.php          # بدون نیاز به دیتابیس (اجرای واقعی منطق)
    php tools/test_food_group_logic_offline.php    # تابع خالص برنامهٔ فیش

      ↳ برای اجرای واقعی «چاپ مجدد» در همین آزمون: FT_TEST_ALLOW_PRINT=1 را تنظیم کنید.
    php tests/SecurityTest.php                     # انتظار: 9/9
    php tests/ArchitectureTest.php                 # انتظار: 4/5 (تنها خطا: فونت woff2 دودویی)

────────────────────────────────────────────────────────────────────────────────
۶) رفتار تازه‌ای که باید ببینید
────────────────────────────────────────────────────────────────────────────────
- تردد نماینده (L_UID) در همان روز: فیش اعضای واجد شرایط در صف چاپ قرار می‌گیرد.
- تردد دوم همان نماینده: فقط یک رکورد خلاصه، بدون فیش تکراری.
- پایش: پیش‌فرض فقط امروز؛ داده‌های گذشته از «گزارش‌ها» با فیلتر بازه.
- ستون «تحویل» و دکمهٔ «ثبت تحویل» در پنل پایش؛ فیش تحویل‌شده دوباره چاپ نمی‌شود.
- تردد با L_UID ناشناخته: هشدار در پیام پردازش + رویداد «L_UID ناشناخته»، بدون فیش گروهی.
- جریان روزانهٔ گروه‌های بیرون از ساختمان:
    ۱) تماس با نگهبانی و گرفتن آمار حضور
    ۲) پنل ← تنظیمات ← گروه‌های غذا ← «غیبت امروز» ← تیک غایب‌ها ← ذخیره
    ۳) همان صفحه شمارش «فیش متوقف‌شده» را نشان می‌دهد (فیش‌های چاپ‌نشدهٔ غایب‌ها متوقف شده‌اند)
    ۴) بعد از تردد نماینده، فقط حاضران فیش می‌گیرند و لیست آن روز قفل می‌شود
    ۵) آن غایب‌ها در گزارش «غایبین» با برچسب «غایب اعلام‌شده — فیش چاپ نشده» می‌آیند
    ۶) اگر بعداً معلوم شد آمده‌اند: تیک را بردارید و ذخیره کنید → فیشش خودکار به صف چاپ برمی‌گردد.

────────────────────────────────────────────────────────────────────────────────
۷) اگر مشکلی پیش آمد
────────────────────────────────────────────────────────────────────────────────
- پیام پردازش (POST /api/process) و رکوردهای food_ticket_group_runs (ستون‌های
  status/error_count/skipped_count) دقیقاً نشان می‌دهند کدام عضو/گروه در چه مرحله‌ای مانده است.
- لاگ‌های activity_logs (دامنهٔ food) و system_logs (context=food_print/food_group) را ببینید.
- خروجی آزمون‌ها/خطاها را بفرستید تا سریع اصلاح شود.

────────────────────────────────────────────────────────────────────────────
گام ۷ — اگر صفحهٔ «طراحی فیش غذا» بعد از به‌روزرسانی سفید شد یا پرید
────────────────────────────────────────────────────────────────────────────
۱. فایل‌های به‌روزرسانی را کامل کپی کنید؛ به‌ویژه این دو فایل تازه:
     food-ticket-web-host.php  (کنار food-ticket.php)
     tools/test_web_host_offline.php
۲. پوشهٔ `food-ticket-web/assets` را دست‌نخورده نگه دارید (هر فایل جاوااسکریپت/CSS تازه هم همان‌جا می‌ماند؛
   میزبان PHP خودش مسیرها را برای مرورگر اصلاح می‌کند).
۳. در Windows PowerShell یا CMD:  php tools/test_web_host_offline.php
   باید ۲۷ بررسی PASS بدهد (بدون نیاز به دیتابیس).
۴. اگر بعد از این هم صفحه بالا نیامد، فایل `error_log` هاست را ببینید؛ پیام
   «لنگرهای index.html تغییر کرده‌اند…» یا «پوشهٔ food-ticket-web/assets خالی…» راهنمای دقیق مشکل است.
۵. هرگز کل پروژه را با پوشهٔ `02-full` جایگزین نکنید (فایل‌های سرورمحور مثل Program.cs و config.php در آن نیستند).
