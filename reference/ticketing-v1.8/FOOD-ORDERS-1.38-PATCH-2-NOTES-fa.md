# یادداشت اصلاحیهٔ UI و گزارش سفارش — Patch 2 (نسخهٔ توسعه)

این اصلاحیه فقط روی سورس توسعهٔ `food-orders-dev` تهیه شده است؛ فایل‌های زنده، سورس اصلی و آرشیوهای قبلی جایگزین نشده‌اند.

## تغییرهای این اصلاحیه

- تقویم کارمند غذای سفارش فعالِ همان شخصِ تأییدشده را نشان می‌دهد، از جمله هنگام سفارش نیابتی؛ روز سفارش‌دار با نشان «سفارش» و کادر زرد مشخص می‌شود. درخواست تقویم نیابتی فقط پس از بررسی مجوز و تطبیق کد ملی در سرور، و فقط برای همان گیرنده، پاسخ می‌دهد؛ فهرست سفارش‌های دیگران به کارمند داده نمی‌شود.
- روزهای عادی در تقویم آبی آسمانی کم‌رنگ‌اند؛ تعطیلات و پنجشنبه/جمعه قرمز روشن‌اند. نشان زرد روز سفارش‌دار در نمای کارمند و مدیر افزوده شده است.
- متن‌های راهنمای اضافی زیر تقویم/عنوان صفحه حذف شده‌اند.
- وضعیت برنامهٔ روز فقط «باز/بسته» است. فیلد و الزام دلیل برای تغییر برنامه یا بستن روز حذف شده، اما کنترل سمت سرورِ مجوز `food.order_close` برای تغییر وضعیت حفظ شده است. الزام دلیل برای اصلاح یک سفارش مدیریتی مستقل باقی است.
- بخش سفارش‌های مدیر دو تاریخ شمسی «از/تا» با تقویم داخلی می‌گیرد؛ جدول و خروجی Excel از همان بازه استفاده می‌کنند. بازهٔ سرور حداکثر ۳۶۶ روز اختلاف دارد.
- بسته‌شدن ناخواستهٔ انتخابگر تاریخ هنگام کلیک پیکان‌های جابه‌جایی ماه/سال در هر دو پیاده‌سازی تقویم رفع شده است.
- خطای نوع `targetId` در Audit خروجی با ارسال شناسهٔ عددی صفر برای خروجی تجمیعی اصلاح شده است.
- دکمه و route اصلاح سفارش از مدیر پشتیبانی پنهان/مسدود شده‌اند؛ route و تابع سرویس سمت سرور فقط ادمین اصلی را می‌پذیرند.
- شمارهٔ cache-busting دارایی‌های تغییرکرده بالا رفته و نسخهٔ `food-ticket-web/assets` با دارایی‌های اصلی همگام شده است.

## آزمون‌های اجراشده در همین سورس

- `python3 -m unittest tests.test_food_orders_static -v` — ۲۲ آزمون موفق.
- `node tests/test_food_order_calendar_node.js` — موفق.
- `node --check` برای فایل‌های JavaScript تغییریافته و استخراج JavaScript درون‌خطی `food-ticket-web/index.html` — موفق.

## محدودیت تأیید

PHP CLI در این محیط موجود نیست؛ بنابراین `php -l` و آزمون PHP آفلاین قابل اجرا نبودند. اتصال MySQL/Access TENTER، اجرای routeها و خروجی واقعی Excel، مرورگر واقعی، Worker و چاپگر نیز از این محیط قابل آزمون نیستند. ساخت آرشیو به‌تنهایی به معنی تأیید staging یا آمادگی برای استقرار واقعی نیست. پیش از استفادهٔ سازمانی باید بسته روی نسخهٔ مقصد تطبیق و در staging واقعی آزموده شود.
